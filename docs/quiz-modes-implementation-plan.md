# Quiz Modes Implementation Plan

## Current State

- **1,632 verses** across 22 categories in `bible-verses.js`
- **Only "First Letter" mode** is active in-game (QuizManager.js `generateQuiz()` blanks 2 words, shows first-letter options)
- **`quizData.missingWord`** already exists on 1,629 verses — generated by `scripts/generate_quizzes.js` which picks random corpus words as distractors
- **Distractor quality is poor**: distractors are random words from other verses (e.g. answer "afraid" vs "weapons", "these", "prosper") — they're not semantically plausible alternatives
- The backup file (`bible-verses.bak.js`) has a comprehension-style `question`/`options`/`answer` plus a `Lie` field per verse
- Renderer currently hardcodes "First letters of missing words are:" label text and expects exactly the first-letter quiz format
- InputHandler clicks are tied to `mcOptions` global array positions
- Quiz area: ~112px from bottom of canvas, 4 buttons at 49x21px each

## The Problem with Current Distractors

The `generate_quizzes.js` script picks random words from the verse corpus. This produces nonsensical options like:

| Answer | Distractors |
|---|---|
| "afraid" | "into", "enjoy", "them" |
| "spirit" | "sins", "instruction", "Christ" |
| "healed" | "will", "give", "children" |

A player can often eliminate 3 options immediately because they don't fit grammatically or contextually. We need **plausible wrong answers** — words that could fit in the blank but aren't correct.

## Phase 1: AI Distractor Generation Script (`scripts/generate_ai_quizzes.js`)

A **separate offline script** that uses any AI model via **OpenRouter** (model-agnostic) to generate high-quality quiz data for all verses. Run once (or when verses change), outputs updated `bible-verses.js`.

### What it does
1. Reads all 1,632 verses from `bible-verses.js`
2. For each verse, sends a prompt to the AI to generate quiz data for **2 quiz types** that need AI:
   - **Missing Word**: Pick 1 significant word, generate 3 plausible distractors that fit grammatically and contextually but are incorrect
   - **True/False**: Generate a false reference and a false category pairing
3. **Category Match** is generated locally (no AI needed) — uses hardcoded **fake ungodly categories** (Fear, Doubt, Greed, Pride, etc.) as distractors. This avoids the problem of real categories being ambiguously applicable to verses, and provides easy encouragement for beginners.
4. Writes the enriched `quizData` back to `bible-verses.js`

### Usage
```
OPENROUTER_API_KEY=sk-... node scripts/generate_ai_quizzes.js [options]

Options:
  --count N     Process only N verses (test quality first)
  --batch N     Verses per API call (default: 20)
  --model NAME  Any OpenRouter model (default: anthropic/claude-sonnet-4.5)
  --delay MS    Between batches (default: 1000)
  --resume      Resume from saved progress
  --dry-run     Preview without API calls
```

### Why a separate script, not runtime AI
- ~82 batched API calls is a one-time cost vs per-game-session cost
- Zero latency during gameplay
- Can be reviewed/edited by hand
- No API key needed on the game server

### Prompt design (batched, 20 verses per call)
The AI is asked for 2 quiz types per verse (missingWord + trueFalse). categoryMatch uses hardcoded fake categories, no AI needed.

Rules for missingWord distractors:
- Must be the same part of speech as the correct word
- Must fit grammatically in the sentence
- Must be plausible in a biblical context but incorrect for THIS verse
- Must be single words, similar length to the correct word

### Category Match — fake ungodly categories
Instead of using real categories (which could ambiguously apply), we use 15 hardcoded ungodly traits as distractors:
`Fear, Doubt, Greed, Pride, Jealousy, Hatred, Selfishness, Despair, Anger, Lust, Deception, Bitterness, Laziness, Vanity, Cowardice`

3 are picked at random per verse. This makes an easy quiz that reinforces the game's spiritual theme.

### Rate limiting / batching
- Process in batches of 20 verses per API call (~82 total calls)
- Add 1-second delay between batches
- Save progress after each batch (resume with `--resume` on failure)
- `--count N` allows testing quality on a subset before full run

### Output format
`quizData` on each verse becomes:
```javascript
"quizData": {
  "missingWord": {
    "question": "Yahweh is on my side. I will not be _____ What can man do to me?",
    "answer": "afraid",
    "options": ["ashamed", "alone", "anxious", "afraid"]
  },
  "categoryMatch": {
    "correctCategory": "Courage",
    "distractors": ["Despair", "Selfishness", "Hatred"]
  },
  "trueFalse": {
    "falseCategory": "Healing",
    "falseReference": "Proverbs 28:1"
  }
}
```

## Phase 2: Pre-Game Quiz Settings (Slider UI)

### Location
On the **menu screen** (`index.html`), visible before clicking Solo. A "Quiz Settings" section with 4 sliders.

### UI Design
```
Quiz Mix
------------------------------------
First Letter (Hard)    ████████░░  30%
Missing Word (Medium)  ████████░░  30%
Category Match (Easy)  ██████░░░░  25%
True / False (Speed)   ███░░░░░░░  15%
                        Total: 100%
```

- Each slider: `<input type="range" min="0" max="100" step="5">`
- When any slider changes, the others **proportionally redistribute** to keep total at 100%
- Display percentage next to each slider
- Defaults: 30 / 30 / 25 / 15

### Constraint handling — keeping total at 100%
When slider X changes to value V:
1. Sum of the other 3 sliders = `remaining = 100 - V`
2. If the other 3 currently sum to 0, distribute `remaining` equally among them
3. Otherwise, scale each of the other 3 proportionally: `other.value = other.value * (remaining / oldSumOfOthers)`
4. Round to nearest 5, fix rounding errors on the last slider

### Data Flow
1. Menu screen stores slider values: `quizSettings = { firstLetter: 30, missingWord: 30, categoryMatch: 25, trueFalse: 15 }`
2. `startGame()` passes `quizSettings` into `init()`, stored as a global
3. `QuizManager.selectMode()` uses cumulative probability from the weights
4. Settings are **client-only** — not sent to server

## Phase 3: QuizManager Refactor

### Unified quiz object format
```javascript
{
  mode: "missing_word",           // or "first_letter", "category_match", "true_false"
  promptText: "The verse with blank or full text",
  questionLabel: "Fill in the blank:",
  options: [
    { text: "loved", isCorrect: true },
    { text: "hated", isCorrect: false },
    ...
  ],
  correctAnswer: "loved"
}
```

### Mode selection logic
Uses `quizSettings` weights with cumulative probability:
```
roll = random 0-99
if roll < firstLetter -> first_letter
else if roll < firstLetter + missingWord -> missing_word
else if roll < firstLetter + missingWord + categoryMatch -> category_match
else -> true_false
```

### Generator functions (one per mode)
- `generateFirstLetterQuiz(verse)` — existing `processVerse()` + `generateQuiz()` logic, unchanged
- `generateMissingWordQuiz(verse)` — reads `verse.quizData.missingWord`, returns standardized object. Falls back to first-letter if data missing
- `generateCategoryMatchQuiz(verse)` — shows full verse, options are correct category + 3 distractor categories from `verse.quizData.categoryMatch`
- `generateTrueFalseQuiz(verse)` — shows verse + a claim (category or reference), 50% chance correct, 50% chance uses false data from `verse.quizData.trueFalse`

### Global state changes
- Replace `gappedVerse`, `firstLetters`, `mcOptions` globals with a single `currentQuiz` object
- `handleQuizAnswer(selectedOption)` checks `selectedOption === currentQuiz.correctAnswer` instead of `selectedOption === firstLetters`

## Phase 4: Renderer + InputHandler Updates

### Renderer (`displayBibleVerse` / `displayMultipleChoiceOptions`)
- Replace hardcoded "First letters of missing words are:" with `currentQuiz.questionLabel`
- Support variable button count (2 for True/False, 4 for others)
- For True/False: render 2 wider buttons ("TRUE" / "FALSE") centered
- For Missing Word: render 4 word buttons (may need slightly wider buttons — 60px instead of 49px)

### InputHandler
- Instead of reading global `mcOptions`, read `currentQuiz.options`
- Click detection adjusts button count and width based on `currentQuiz.mode`

---

## Phase 5: Game Loop Integration

### `game.js` changes
- Replace `gappedVerse`, `firstLetters`, `mcOptions`, `answerFullVerse` with `currentQuiz`
- `uiState.currentVerse` becomes:
  ```javascript
  currentVerse: {
    text: currentQuiz.promptText,
    reference: verse.Reference
  },
  quiz: {
    mode: currentQuiz.mode,
    questionLabel: currentQuiz.questionLabel,
    options: currentQuiz.options
  }
  ```
- `onQuizOptionClick` callback passes the selected option object, QuizManager checks `isCorrect`
